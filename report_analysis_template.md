# Analysis Report Support Notes

## Parallel Programming Approach

The simulation solves a 2D heat diffusion problem over a rectangular grid. Boundary cells are fixed at a constant temperature, while interior cells are updated iteratively from their four direct neighbours. The serial implementation is used as the numerical baseline.

OpenMP parallelizes the shared-memory version by distributing the outer grid-row loop across threads. Each thread updates a separate subset of interior rows for the current timestep. Because each update reads from the old grid and writes to a separate new grid, no thread writes to the same grid cell during the update phase.

MPI parallelizes the distributed-memory version by decomposing the grid into horizontal row blocks. Each MPI process owns a block of rows and exchanges halo rows with neighbouring processes before each timestep. The root process gathers all local row blocks after the final timestep to reconstruct the complete grid.

The hybrid version combines both ideas. MPI distributes row blocks across processes, and OpenMP parallelizes the row updates inside each process. The total parallelism for the hybrid implementation is calculated as:

```text
total parallelism = MPI process count x OpenMP threads per process
```

## Accuracy Measurement

Accuracy is evaluated using Root Mean Square Error (RMSE) against the serial implementation. For each parallel run, the final grid is compared with a serial baseline generated using the same grid size, timestep count, and alpha value.

```text
RMSE = sqrt((sum of squared differences) / number of compared cells)
```

Only interior cells are included in the RMSE calculation because the boundary cells are fixed by the problem definition. The RMSE values are written to:

```text
results/rmse.csv
```

The accuracy plot generated by `scripts/analyze_results.py` is saved in:

```text
results/plots/
```

## Timing, Speedup, and Efficiency

Execution time is measured inside each implementation around the main simulation loop. For MPI and hybrid runs, the reported time is the maximum elapsed time across all MPI processes, which represents the true parallel completion time.

Speedup is calculated as:

```text
speedup = serial execution time / parallel execution time
```

Parallel efficiency is calculated as:

```text
efficiency = speedup / parallelism x 100
```

The derived metrics are written to:

```text
results/metrics.csv
```

The generated plots are written to:

```text
results/plots/
```

## Suggested Report Discussion

The OpenMP implementation is expected to reduce execution time as the number of threads increases, especially for larger grids where the computation per timestep is high. Efficiency may decrease at higher thread counts due to thread management overhead, memory bandwidth limits, and synchronization at the end of each parallel loop.

The MPI implementation benefits from distributing the grid across processes, but communication overhead increases because neighbouring processes exchange halo rows at every timestep. Larger grid sizes usually improve MPI scalability because the computation-to-communication ratio becomes more favourable.

The hybrid implementation can improve performance when a cluster node has multiple cores per MPI process. It reduces the number of MPI processes compared to a pure MPI run while still using multiple cores through OpenMP. Its performance depends on the balance between MPI communication cost and OpenMP threading overhead.

Low RMSE values indicate that the parallel implementations preserve the numerical behaviour of the serial baseline. If RMSE is zero or very close to zero, the parallel decomposition and halo exchange are producing equivalent results for the tested parameters.
